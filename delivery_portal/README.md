# بوابة شركة التوصيل

صفحة ويب مستقلة (HTML/CSS/JS عادي — بلا أي إطار عمل أو خطوة بناء) تتيح لموظف شركة
التوصيل رؤية الطلبات المُسندة إليه من منصة `balla` وتحديث حالتها بحدثين فقط:
**تأكيد الاستلام** (`pick-up`) و**تأكيد الوصول للزبون** (`mark-arrived`). لا تدير
هذه الصفحة سائقين أو حسابات فرعية — الشركة تُدار عبر حساب دخول واحد فقط
(`DeliveryCompany.account` في الباكند)، ويُنشأ يدوياً من `/admin/core/deliverycompany/`.

## البنية

```
delivery_portal/
├── index.html      شاشتا الدخول ولوحة التحكم
├── css/style.css
├── js/
│   ├── config.js   عنوان الـ API — الملف الوحيد الذي يحتاج تعديل عند النشر
│   ├── api.js       تسجيل الدخول عبر JWT + تجديد التوكن تلقائياً
│   └── app.js        منطق العرض والإجراءات
└── README.md
```

## التشغيل محلياً

1. شغّل الباكند كالمعتاد: `python manage.py runserver` (يعمل على `http://127.0.0.1:8000` افتراضياً).
2. تأكد أن `js/config.js` يشير إلى نفس العنوان (القيمة الافتراضية مضبوطة على ذلك أصلاً).
3. اخدم هذا المجلد بأي سيرفر ستاتيك بسيط، مثلاً:
   ```
   cd delivery_portal
   python -m http.server 8765
   ```
   ثم افتح `http://127.0.0.1:8765`.

   **لا تفتح `index.html` مباشرة من نظام الملفات (`file://`)** — بعض المتصفحات
   تمنع `fetch` من أصل `file://`. لازم سيرفر ولو بسيط.

## النشر على سيرفر ودومين حقيقي (لاحقاً)

هذه صفحة ستاتيكية بالكامل — لا تحتاج Node أو أي وقت تشغيل خادم خاص بها، فقط
استضافة ملفات ثابتة. الخطوات:

1. **عدّل `js/config.js`** واجعل `API_BASE_URL` يشير لدومين الباكند الحقيقي، مثلاً:
   ```js
   const CONFIG = { API_BASE_URL: 'https://api.balla.example.com/api' };
   ```
2. **ارفع محتوى هذا المجلد** لأي استضافة ستاتيك: Nginx على نفس سيرفر الباكند
   (كمسار مثل `/delivery/` أو دومين فرعي `delivery.balla.example.com`)، أو أي
   خدمة استضافة ستاتيك خارجية. لا حاجة لأي إعداد خاص غير خدمة الملفات كما هي.
3. **أضف دومين البوابة إلى `CORS_ALLOWED_ORIGINS`** في `balla/settings.py` على
   الباكند (هذا إلزامي — بدونه سيرفض المتصفح كل الطلبات بصمت):
   ```python
   CORS_ALLOWED_ORIGINS = [
       ...
       "https://delivery.balla.example.com",
   ]
   ```
   (ملاحظة: `CORS_ALLOW_ALL_ORIGINS` مفعّل تلقائياً فقط أثناء `DEBUG=True` — في
   الإنتاج لازم تُدرَج القيمة صراحةً كما أعلاه.)
4. **استخدم HTTPS إلزامياً في الإنتاج** — الصفحة تُرسل وتخزّن توكن JWT في
   `localStorage`؛ تشغيلها عبر HTTP عادي على دومين عام يعرّض هذه التوكنات للخطر.

### مثال إعداد Nginx (لو استضفتها كمسار على نفس سيرفر الباكند)

```nginx
location /delivery/ {
    alias /var/www/delivery_portal/;
    try_files $uri $uri/ /delivery/index.html;
}
```

## إعداد حساب الشركة (خطوة تُنفَّذ مرة واحدة)

راجع القسم الخاص بهذا في خطة التوصيل — باختصار:

1. أنشئ صفاً في `/admin/core/deliverycompany/` باسم الشركة.
2. أنشئ حساب `User` عادي (اسم مستخدم + كلمة مرور) للشركة.
3. اربط الحساب بحقل `account` في صف الشركة، وفعّل `is_active`.
4. سلّم بيانات الدخول (اسم المستخدم/كلمة المرور) لموظف الشركة ليدخل من هذه
   الصفحة مباشرة.

## الأمان

- كل الإجراءات (`pick-up`, `mark-arrived`) محمية على مستوى الباكند بحيث لا
  ينفّذها إلا حساب الشركة المُسنَد إليه الطلب تحديداً (`DeliveryOrderViewSet._company_account_or_403`)
  — حتى لو تسرّب رابط الصفحة، لا يقدر أي حساب آخر ينفّذ إجراءً على طلب لا يخصه.
- لا يوجد تسجيل ذاتي أو نسيان كلمة مرور من هذه الصفحة عمداً — الحساب الوحيد
  يُدار يدوياً من طرفكم عبر لوحة الإدارة.
